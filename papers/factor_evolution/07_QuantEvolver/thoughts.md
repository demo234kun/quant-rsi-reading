# QuantEvolver 个人思考

## 最该偷的设计：Diversity-Complementarity Reward

大多数因子挖掘论文只奖励 IC 高，结果就是模型学会"微调上一条好因子"，产出一堆相关因子，组合起来没增量。QuantEvolver 把"和已有因子库互补"写进奖励，这是结构性对抗趋同，不是靠 prompt 提醒。

个人做因子研究时，可以照搬：每加一条新因子，先算它和已有因子库的相关系数，只有 IC 高且和现有库相关性低才入库。这个规则不需要 RFT 也能执行。

## Prompt-loop vs 权重更新：个人系统怎么选

- 如果你每次研究 session 之间是断开的（不重训模型），prompt-loop 够用；
- 如果你想让自己的"挖因子手感"随时间进化，RFT 路线是唯一答案——但成本是要有 seed 数据和训练管线。

对个人开发者，现实路径是：**先用 prompt-loop + 结构化记忆（发现树）跑起来，攒够几百条成功/失败案例后，再考虑 RFT**。这正是 Dream-RSI 的"先存树，再做梦"。

## 与本库其他文章的关系

- 它是 03_Astar 的**因子挖掘版**——同样的"经验训进权重"哲学，不同的任务。
- 它和 04_Dream-RSI 互补：Dream-RSI 把经验留在元策略层（不重训），QuantEvolver 把经验训进权重（重训）。两种 τ 传播路径。
