## 2. 核心精读问答

### Q1 研究问题：这篇论文试图解决什么问题？

**背景**：AI 系统迭代四步——提方向 → 写代码 → 训练 → 评估去留。后两步已自动化，**第一步"提方向"没有**。

**痛点**：
1. 太吃综合判断（业务 + 数据 + 架构 + 训练动态）
2. 验证太贵（一次完整训练以天计）
3. 直接问通用大模型效果差——瓶颈不是聪明，是**经验放在哪里**，通用模型没读过这个系统的失败记录

**目标**：用一个专用模型把"下一步改哪儿"训练进权重，并通过数据回流实现递归自我改进。

### Q2 相关研究

| 提案者 | 单提案真实执行成功率 |
|---|---|
| GPT-5.5 | 0.3071 |
| 人类专家 | 0.3229 |
| **Astar-8B** | **0.6786** |
| Astar-0.6B | 0.5435 |

> 通用模型和人类专家打平且都不及格；本文缺口是"领域经验"未进入通用模型。

### Q3 解决方案：论文如何解决？

**核心思路：不注入，训练**（把经验放进权重，而非靠 prompt 注入历史）。

**① 数据工程：几百条 commit → 几万条样本**
- **Pairwise 扩展**：任意两版本配对比较，几百条 → 几万条；胜负看完整 loss 曲线，不看单点
- **三段过滤**：可达性分析（删死代码）→ AST 归一（删 print/注释/格式）→ 配置白名单（只留算法变量）
- **语义过滤**：LLM 判断有无演化意图，产出三层级 hints（科室→检查→剂量）

**② 三阶段训练（培养住院医）**

| 阶段 | 数据量 | 学什么 |
|---|---|---|
| Mid-training | 112B tokens | 在完整演化历史上 next-token 预测，学会写结构化方向 |
| SFT | 81.1M 正样本 tokens | 只跟成功病例学（复合指标：末步 loss + 末 k 步均值 + 稳定性惩罚） |
| RL（GRPO） | 8.06M tokens | 放手探索新方向 |

**③ 奖励模型（教练，关键组件）**
- 验证一个方向要几天、RL 要即时反馈 → 训一个二分类 RM："这个方向会不会降 loss"
- 身兼三职：RL 奖励函数 / 候选排序器 / 离线指标裁判
- **AUC 0.8487**（人类专家 0.6142、最强通用模型 0.5997）

**④ 递归闭合**：
```
Astar 提方向 → Code Agent 实现 → 训练评估 → 部署
   ↑                                              ↓
   └── 结果采样/降噪/结构化成新样本，回流训练 Astar ┘
```

### Q4 可复现细节

- **数据**：系统内部 commit/演化历史（数百条，pairwise 扩展到数万）；外部不可得
- **训练**：mid-training 112B tokens、SFT 81.1M、RL 8.06M tokens
- **方法**：GRPO + 二分类奖励模型
- **消融**：base RM@1=0.0380 → mid-training 0.6041 → +SFT 0.6853 → +RL 0.7183；**最大台阶是领域经验一次性注入**
- **参数量**：8B（主）/ 0.6B（小）；其他硬件、训练时长未披露
- **复现坑**：奖励模型 15% 误判同时流入策略梯度、排序、离线裁判三处

### Q5 实验部分

**生产结果（Lazada 广告召回）**：
- 两周、20 轮连续迭代：离线 Hitrate@200 累计 **+23.6%**
- 5 天线上 A/B：**GMV +4.86%、广告收入 +1.82%、点击 +0.84%、订单 +1.79%**（p<0.05）
- 效率：人工每周 Θ(1)–Θ(10) 方向、每方向 Θ(1)–Θ(10) 小时 → Astar 每周 Θ(100) 方向、每方向 Θ(1)–Θ(10) 分钟

**两个真实提案案例**：
1. **RQ-VAE 码本**：decoder 共享 FFN 拟合粗/细两层码本互相打架 → 换 MoE，每层一个专家按层级路由，FLOPs 中性
2. **Muon 优化器改造**：Muon 把梯度谱所有奇异值拉平到 1，噪声 bulk 被一起放大 → 用 Marchenko-Pastur 边界做频谱降噪，无学习参数

### Q6 创新点与可借鉴点

- **方法创新**：领域经验"训练进权重"而非 prompt 注入；数据闭环回流
- **工程创新**：pairwise 扩展 + 三段过滤把少量记录变训练集；RM 三职合一
- **可迁移**：把自己系统的历史 commit/失败记录结构化，用专用小模型而非通用大模型做"下一步决策"
- **安全设计**：增量校准（周期抽样真实验证）+ 部署前真实 A/B 外圈刹车

### Q7 不足与局限

1. **评估有循环**：离线指标用自家 RM 当裁判，RM 同时是 RL 奖励和排序器
2. RM 约 15% 误判，错误同时流进三处
3. 缺三个基线：in-context 历史注入、RM+简单搜索、AlphaEvolve 式演化+同一 RM
4. loss ≠ 业务（召回 +23.6% 到 GMV +4.86% 隔着排序和出价）
5. 单系统、单窗口；p 值给了但置信区间没给
6. 三层级 hints 是预定义分类法，探索天花板被框住
7. 不可完全复现（数据/模型内部）

## 3. 范式提炼

### 逻辑范式
```
痛点（"提方向"未自动化）→ 验证（通用模型/人类都不及格）
  → 方案（经验训进权重：数据工程+三阶段训练+RM）
  → 闭合（产物回流改进改进者）→ 生产验证（A/B）
```

### 技术范式
> "专用小模型 + 奖励模型 + 数据回流"：用系统自身的历史经验训练一个决策者，决策者的产物又成为新训练数据；但必须用独立的外圈验证（A/B）防止评估循环。
