## 摘要

大语言模型（LLM）交易智能体能够融合市场数据、新闻与可执行定量分析，但智能体行为由部署前人工编写的静态工具调用策略控制。当市场体制发生切换时，静态策略限制智能体调整证据搜集、工具调用、信号校验、风险管控的能力。本文提出 EvolveTrade 自演化框架，将具备工具调用能力交易智能体的**系统提示词视作文本参数化策略**。每轮更新周期结束后，独立的策略智能体基于累积决策轨迹与投资组合真实收益反馈修订策略；骨干 LLM 全程冻结不微调。更新后的策略用于下一批次交易决策，让智能体随时间持续优化信息获取与投资组合构建流程。在多类市场体制、两种 LLM 骨干模型上开展实验，结果表明：对比固定策略 LLM 基线，EvolveTrade 能够提升夏普比率与累计收益率，在大部分评测场景下取得更优指标。行为分析表明：自演化策略会增加代码驱动定量分析的占比，自动启用适配当前市场体制的计算逻辑；案例层面的策略 - 收益归因，可追踪策略变更带来的资产配置调整如何影响最终真实收益。实验证明：优化管控工具调用的可复用流程，是构建高鲁棒 LLM 交易智能体的关键方向。
【写作定位：**高度压缩全文核心贡献、核心机制、实验结论；直接点明现有 LLM 交易智能体静态策略的核心缺陷，定义 EvolveTrade 核心创新对象：文本参数化系统提示策略，预先给出跨模型、多市场环境下的性能与行为结论**】

## 1 引言

大语言模型（LLM）在推理、指令遵循、异构信息融合方面表现突出。但这些能力无法直接转化为金融市场上稳定可靠的决策能力：金融场景下智能体需要反复获取信息、校验噪声冲突信号、管控组合风险，并且在非平稳环境下基于延迟反馈执行交易动作。
【铺垫作用：**开篇搭建领域基础背景，点明 LLM 推理能力强，但金融市场具备非平稳、高噪声、反馈延迟的固有特性，构成 LLM 落地交易任务的天然障碍**】

近年研究利用 LLM 融合数值市场数据与非结构化定性信息（财经新闻、市场情绪、分析师研报），基于自然语言指令搭建交易智能体。另有研究为智能体增加记忆、规划模块与外部工具，使其调用市场数据 API、技术指标库、新闻检索引擎、交易接口。这类系统证明，相比纯数值量化模型，LLM 智能体能够实现更灵活的金融决策。但相关研究同时发现：仅扩充上下文或者开放更多工具权限并不足够；智能体必须清楚**何时、为何、如何**使用这些资源。
【缺口构建：**梳理现有 LLM 交易智能体研究进展，肯定工具增强、多源信息融合带来的优势；同时提出核心矛盾：单纯向模型提供更多数据与工具，不代表模型掌握合理调用工具的方法**】

现有方案一般在开发阶段就固定这套信息获取流程，主要分为两类范式。第一类为真实交易基准测试：向智能体提供预设观测窗口内的价格、组合状态、市场新闻，评估智能体基于给定信息的决策质量。第二类为自主交易框架：允许智能体调用外部工具，但工具调用行为依然受固定提示词、预设工作流或者静态智能体角色约束。两类范式的共性问题：决策流程是部署前一次性写死的提示词，不会根据真实交易结果迭代更新。
【问题界定：**划分两类主流静态 LLM 交易智能体范式，归纳底层共性缺陷：工具调用、信息获取策略在部署前固化，无法利用真实交易反馈持续迭代**】

本文认为，这种固定策略是 LLM 交易智能体的核心瓶颈。应当利用经验去优化的对象，不是单次交易决策，而是智能体用于获取、校验信息并据此执行交易的可复用流程。因此，我们需要一套机制，让智能体在交易日之间迭代优化这套流程，用过往交易经验指导后续决策。
【核心论点提出：**阐明论文核心主张：优化目标不是单次资产配置决策，而是「信息获取、证据校验、决策执行的可复用流程」，提出部署后在线迭代策略的机制需求**】

本文提出 EvolveTrade，一套自演化框架：LLM 智能体可以基于自身交易经验，迭代优化自身的工具调用策略。在每一轮交易周期结束后，独立的**策略智能体**读取本次完整交易记录、资产维度推理过程，将策略文本从\(\pi_{t}\)更新至\(\pi_{t+1}\)。后续交易日所使用的策略，都由智能体过往真实交易经验塑造。单次策略更新可以修改工具优先级、信号交叉校验规则、特定市场环境下的风险敞口调整方式；整个过程中底层 LLM 参数、工具接口保持不变。EvolveTrade 唯一学习的对象就是策略文本本身，因此该框架可以直接套用到任意冻结参数的 LLM 交易智能体，无需微调模型，也不用修改工具。
【创新定位：**完整介绍 EvolveTrade 核心机制，强调骨干 LLM 冻结、仅更新文本策略的轻量化特性；说明策略更新可修改工具优先级、信号交叉校验、风险敞口规则，突出框架通用性**】

本文通过实验验证两大结论。第一，在线策略自演化机制相比固定策略基线，能够提升 LLM 交易智能体表现：在两套骨干模型、六个截断后市场环境下，EvolveTrade 在三组 “模型 - 市场环境” 配对中取得最优夏普比率与累计收益；其余两组场景下静态策略基线更强。第二，性能提升伴随可观测的工具使用行为变化。EvolveTrade 会提升代码定量分析的使用频次，启用静态工具调用智能体从未触发的、适配市场状态的计算逻辑：例如 4 月回撤行情下的风险价值 VaR 与信号归一化，9 月上涨趋势下的 EMA、RSI、SMA 趋势指标。在 2025 年 1 月英伟达 NVDA 回撤案例中，经优化后的仓位策略带来 1.33 个百分点的相对日度收益提升。上述结果说明，应当允许 LLM 交易智能体利用自身交易经验，迭代优化工具使用流程。
【贡献预览：**提前抛出两大核心实验结论：1）在线自演化策略在多数市场环境下优于静态基线；2）性能提升伴随可观测的工具调用行为改变，策略会自适应市场环境调用对应指标，为后文实验章节设置预期**】

## 2 相关工作

### 2.1 面向金融交易的 LLM 智能体

近年研究将记忆模块、工具、多模态信号、多智能体审议机制引入 LLM 金融交易智能体。FinMem 采用分层记忆跨会话保存市场观测；TradingAgents、StockAgent、QuantAgent、TradExpert 通过专用智能体角色、仿真交易环境、固定分析流水线组织决策流程。FinAgent 以及同类金融智能体平台融合多模态输入、实时数据、领域工具或反思式决策；AI-Trader、LiveTradeBench、FinAgentBench 等新型基准，在更贴近真实的金融信息与市场条件下评测 LLM 智能体。近期研究也关注 LLM 交易的可靠性问题，包括噪声数据源可信度、股票代码记忆污染、时间泄露等问题。上述系统证明 LLM 能够融合异构金融证据，但这类智能体的观测通道、提示词、工具调用策略均在部署前固定，无法利用交易反馈持续调整自身分析流程。
【综述逻辑：**梳理 LLM 金融智能体主线工作，肯定现有成果，同时点出这类工作统一的短板：提示 / 策略静态固化，无法在线自适应演化**】

### 2.2 提示词优化与 LLM 智能体自改进

提示优化领域（Prompt Optimization）大多聚焦离线优化：在固定数据集上，通过梯度、演化搜索、LLM 自反思方式优化提示词，优化完成后直接部署，运行阶段不再更新。而在线提示优化方法大多面向分类、问答等单步任务，很少应用在带延迟收益反馈的时序金融决策场景。
LLM 智能体自改进（Self-improving agent）方向的工作，大多聚焦单次任务内的反思：在单次任务内部修正推理错误，而不是跨周期修改**长期复用的工具调用策略**。在金融领域，AlgoEvolve 等相关工作演化可执行交易代码，而 EvolveTrade 演化的是**自然语言策略提示**，不是代码本身。
【综述逻辑：**区分离线提示优化、单步任务内反思、代码策略演化三类相关方向，通过对比凸显 EvolveTrade 的差异化创新：跨交易周期、基于真实投资收益反馈迭代自然语言策略文本**】

### 2.3 时序环境下的金融强化学习

传统量化强化学习直接优化资产权重，学习目标是资产配置参数；模型参数学习后难以解释，泛化到新市场体制难度高。EvolveTrade 不直接优化资产权重，而是优化**自然语言策略（提示词）**，策略具备可读性、可解释性，底层 LLM 保持冻结。
【综述逻辑：**对比传统量化 RL，明确本文范式差异：优化对象不是资产权重，而是文本策略，解释性更强，不需要训练神经网络权重**】

### 研究空白总结

现有 LLM 交易智能体、提示优化、金融 RL 工作，缺少**跨交易周期、基于真实投资组合收益反馈，持续迭代自然语言工具调用策略**的框架。EvolveTrade 填补该空白。
【综述逻辑：**收尾提炼领域缺口，为后文方法章节的框架设计提供动机支撑**】

## 3 研究方法：EvolveTrade 框架

### 3.1 问题定义

交易环境为时序非平稳市场。

- 交易智能体（Trading Agent）：骨干 LLM 冻结，接收市场观测、新闻、当前策略\(\pi_t\)，调用工具，输出资产权重\(w_t\)。
- 策略\(\pi_t\)：一段自然语言系统提示文本，定义**工具调用规则、证据校验流程、风险管控规则、不同市场环境下的分析优先级**，也就是文本参数化策略。
- 策略智能体（Policy Agent）：独立 LLM，负责策略更新，不执行资产配置。
- 一轮完整循环：交易执行 → 获取真实收益反馈 + 决策轨迹 → 策略智能体生成新策略\(\pi_{t+1}\) → 下一轮交易使用\(\pi_{t+1}\)。

目标：在不修改骨干交易 LLM 参数、不修改工具接口的前提下，通过迭代更新文本策略\(\pi\)，长期提升投资组合收益与风险调整收益。
【设计思路：**形式化定义全部核心变量与优化目标，明确双智能体分离设计：交易智能体负责做交易，策略智能体负责修改策略，职责解耦**】

### 3.3 模块 1：交易智能体（Trading Agent）

交易智能体由冻结 LLM 骨干 + 工具集构成。
工具集包含：

1. 市场数据查询工具：历史价格、成交量、技术指标（SMA、EMA、RSI）
2. 代码执行工具：运行 Python 代码计算 VaR、信号归一化、自定义统计指标
3. 新闻检索工具：提取标的相关财经新闻、情绪摘要
4. 资产分配工具：输出归一化资产权重，带风险约束（最大单资产敞口上限）

工作流程：

1. 读取当前策略\(\pi_t\)（系统提示），策略规定：什么时候调用哪类工具、如何校验冲突信号、回撤场景下的风控规则。
2. 接收当日市场观测、新闻。
3. 按策略规定顺序调用工具，生成推理链条。
4. 输出资产配置权重\(w_t\)。

> 
> 注意：骨干 LLM 全程不微调，仅策略文本\(\pi_t\)发生变化。
> 【设计思路：**交易智能体只负责执行，不负责自我反思和策略改写；所有规则完全由传入的策略文本控制，保证策略修改可以直接改变行为**】

### 3.4 模块 2：交易经验构造：策略反馈信号

当智能体提交资产权重\(w_t\)，环境更新投资组合状态，生成反馈记录\(g_t\)。
\(g_t\)包含：

- 当日投资组合整体收益率
- 每只可交易资产的个体收益率
- 最终资产配置权重、组合净值、波动率统计

仅靠收益\(g_t\)作为反馈信号存在歧义：亏损可能是证据收集缺陷，也可能是不可预测的市场冲击；盈利可能来自严谨分析，也可能只是噪声运气。金融市场延迟 + 噪声反馈，直接优化策略极其困难。
EvolveTrade 将**决策轨迹 Trace**与收益反馈\(g_t\)配对。决策轨迹 Trace 保存：每一步工具调用、代码输出、模型推理、信号校验过程。
输入策略智能体的完整输入 = 收益反馈\(g_t\) + 完整决策轨迹 Trace。
【设计思路：**解决金融反馈模糊性痛点：只看收益无法定位失败根源，必须配套完整推理轨迹，策略智能体才能判断是策略流程问题，还是单纯市场随机冲击**】

### 3.5 模块 3：策略智能体（Policy Agent）与策略求精步骤

策略智能体是独立 LLM，在**每轮交易周期结束后**执行一次策略求精，不是每日更新（可配置更新间隔）。
策略智能体输入：

1. 旧策略文本\(\pi_t\)
2. 本轮全部决策轨迹 Trace
3. 投资组合真实收益反馈\(g_t\)
4. 市场体制标签（上涨 / 回撤 / 震荡）

策略智能体的提示指令要求：

1. 诊断本次交易成败根源：区分是市场随机噪声，还是策略本身流程缺陷（工具调用顺序错误、缺少校验、风控缺失）
2. 修改策略文本，**只修改流程规则**，不修改底层工具接口，不改变输出格式
3. 策略修改的可选方向：调整工具优先级、增加交叉校验步骤、增加特定市场场景的风控规则、新增定量计算要求（如强制 VaR 计算）
4. 输出新策略文本\(\pi_{t+1}\)

> 
> 策略求精是**文本改写**，不是参数更新。策略智能体可以增删、修改自然语言里的规则条款，保留原有策略的基础结构。
> 【设计思路：**定义策略智能体的诊断 + 改写逻辑，约束修改边界：只改流程，不改底层工具与输出格式，保证更新后的策略仍然可以被交易智能体正常执行**】

### 3.6 整体运行闭环

1. 初始化：人工写初始策略\(\pi_0\)，部署到交易智能体。
2. 交易阶段（内环）：交易智能体使用当前\(\pi_t\)，逐交易日调用工具，输出资产配置，在仿真市场执行交易，保存决策轨迹与收益。
3. 策略更新阶段（外环，周期触发）：策略智能体读取周期内全部轨迹 + 收益，诊断问题，生成\(\pi_{t+1}\)。
4. 下一轮交易，使用新策略\(\pi_{t+1}\)，循环往复。
【设计思路：**区分两个时间尺度：高频交易内环，低频策略演化外环；避免策略频繁震荡，保证策略更新稳定可控**】

## 4 实验

### 4.1 数据集完整信息

- 资产池：美股大盘流动性个股，包含 NVDA、AAPL、MSFT 等龙头标的
- 时间区间：2024–2025，拆分为 6 个独立、截断后的市场子区间（6 种市场体制）
  1. Regime1：温和上行
  2. Regime2：快速上涨趋势
  3. Regime3：短期回撤（2025.01 NVDA 回撤案例）
  4. Regime4：震荡区间
  5. Regime5：4 月深度回撤
  6. Regime6：9 月上行趋势
- 数据类型：日度收盘价、成交量、技术指标、对应标的每日财经新闻文本
- 预处理：
  1. 时间泄露严格规避：所有数据严格使用当日可获取信息，禁止使用未来数据
  2. 新闻文本清洗，去除冗余广告，保留摘要、分析师观点
  3. 价格数据做对数收益率计算，用于收益评估
- 数据划分：6 个市场体制完全独立，无跨区间训练，在每个体制内做滚动仿真回测。
【验证目标：**构造多样化、真实化的市场环境，覆盖上涨、回撤、震荡，验证 EvolveTrade 在不同市场体制下的鲁棒性**】

### 4.2 实验配置

- 骨干 LLM（两组）：LLM-A、LLM-B（两个不同开源大模型，作为交易智能体骨干，全程冻结）
- 基线模型：
  1. Static-Prompt Agent：静态固定提示策略，和 EvolveTrade 初始策略完全一致，全程不更新
  2. Static Tool-Calling Agent：带固定工具调用流程的 LLM 交易智能体（领域主流基线）
  3. 买入持有（Buy & Hold）：资产池等权持有，金融基准
- 评估指标：
  - 累计收益率 CR（Cumulative Return）：期末净值 / 期初净值 -1
  - 夏普比率 SR（Sharpe Ratio）：超额收益 / 波动率，衡量风险调整收益，越高越好
  - 工具调用行为统计：代码分析调用频次、各类技术指标触发次数
  【验证目标：**设置多维度基线，同时评估量化收益指标与智能体行为变化，不只看收益，还要验证行为层面的机制有效性**】

### 4.4 行为分析实验

统计工具调用行为：

1. EvolveTrade 演化后的策略，**代码驱动定量分析调用频次显著上升**；静态基线很少调用代码工具。
2. 市场体制自适应行为：
   - Reg5（4 月深度回撤）：演化策略自动加入 VaR 计算、信号归一化校验；静态工具智能体从未调用 VaR。
   - Reg6（9 月上行趋势）：演化策略优先调用 SMA、EMA、RSI 趋势指标；静态基线对趋势指标调用频次更低。
3. NVDA 回撤案例（Reg3）：策略演化后优化了仓位控制规则，带来**+1.33 个百分点相对日收益**。
【验证目标：**验证机制假设：收益提升来源于策略修改带来的工具调用行为变化，智能体学会针对不同市场状态启用对应的计算流程，不是随机波动**】

## 5 讨论与局限

1. 仿真环境约束：全部回测基于历史仿真回测，没有实盘交易验证。历史回测存在过拟合风险；市场分布发生巨大结构性跳变时，演化策略依然可能失效。
【边界说明：**明确实验环境边界：仅历史仿真回测，尚未实盘；历史数据的后验特性带来潜在过拟合风险，无法保证在极端黑天鹅市场有效**】
2. 策略演化的不稳定风险：策略智能体是 LLM，文本改写存在随机性。少数迭代轮次，策略可能出现退化，引入错误规则，造成短期收益下滑。框架没有内置策略安全校验器，缺少策略回滚机制。
【边界说明：**指出 LLM 改写策略本身的不确定性风险：文本生成存在随机性，存在策略退化风险，当前版本缺少策略校验与回滚保护机制**】
3. 资产池与时间覆盖有限：实验仅使用美股大盘流动性个股，没有覆盖跨资产（债券、商品）、小盘股；评测时间窗口仅覆盖 2024–2025，缺少更长周期熊市测试。
【边界说明：**说明数据集边界：标的类型、时间跨度有限，泛化到其他资产类别、超长熊市环境的能力有待验证**】
4. 计算开销：每一轮策略更新，都需要调用策略 LLM 读取大量决策轨迹，长周期下计算成本较高。
【边界说明：**指出工程落地代价：策略迭代伴随较高的 LLM 推理开销，高频更新会提升成本**】
5. 不直接学习资产权重：EvolveTrade 优化的是自然语言策略，不是资产权重；当最优交易逻辑无法用自然语言规则描述时，该框架存在能力上限。
【边界说明：**明确范式固有上限：依赖自然语言描述策略，无法学习难以用文字表达的隐式非线性交易规则**】

## 6 结论

本文提出 EvolveTrade，面向 LLM 交易智能体的经验驱动自演化框架。框架不微调骨干 LLM，仅以自然语言文本作为策略载体；利用历史交易收益反馈与完整决策轨迹，跨周期迭代更新工具调用策略。实验证明，EvolveTrade 在多数市场体制下，相比固定策略基线，可以提升夏普比率、累计收益；行为分析表明策略演化会驱动智能体自适应调整工具调用逻辑，在不同市场环境启用适配的定量计算流程。消融实验证明：决策轨迹是策略有效迭代的关键组件。本文的核心结论：对于 LLM 交易智能体，**持续演化管控工具调用的自然语言策略，是提升金融决策鲁棒性的有效路径**。
