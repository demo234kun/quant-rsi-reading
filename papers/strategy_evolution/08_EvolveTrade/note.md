# EvolveTrade: Experience-Driven Policy Refinement for Self-Evolving LLM Trading Agents

## 1. 论文基础元信息

- 论文标题：EvolveTrade: Experience-Driven Policy Refinement for Self-Evolving LLM Trading Agents
- 作者：Sehee Kim, Yumin Choi, Minki Kang, Sung Ju Hwang
- 机构：KAIST（韩国科学技术院）、DeepAuto.ai
- 发表会议 / 期刊：arXiv 预印本（2609.17632v1，暂未正式顶会 / 期刊发表）
- 论文链接：[https://arxiv.org/html/2609.17632v1](https://arxiv.org/html/2609.17632v1)
- 代码链接：**论文未公开代码**
- 关键词：LLM 智能体；交易智能体；提示词优化；自演化智能体；工具调用；金融时序决策；非平稳市场；文本策略
- 摘要：
大语言模型（LLM）交易智能体能够融合市场数据、新闻与可执行定量分析，但智能体行为由部署前人工编写的静态工具调用策略控制。当市场体制发生切换时，静态策略限制智能体调整证据搜集、工具调用、信号校验、风险管控的能力。本文提出 EvolveTrade 自演化框架，将具备工具调用能力交易智能体的**系统提示词视作文本参数化策略**。每轮更新周期结束后，独立的策略智能体基于累积决策轨迹与投资组合真实收益反馈修订策略；骨干 LLM 全程冻结不微调。更新后的策略用于下一批次交易决策，让智能体随时间持续优化信息获取与投资组合构建流程。在多类市场体制、两种 LLM 骨干模型上开展实验，结果表明：对比固定策略 LLM 基线，EvolveTrade 能够提升夏普比率与累计收益率，在大部分评测场景下取得更优指标。行为分析表明：自演化策略会增加代码驱动定量分析的占比，自动启用适配当前市场体制的计算逻辑；案例层面的策略 - 收益归因，可追踪策略变更带来的资产配置调整如何影响最终真实收益。实验证明：优化管控工具调用的可复用流程，是构建高鲁棒 LLM 交易智能体的关键方向。
- TLDR（极简一句话总结）：提出 EvolveTrade，在冻结交易 LLM 参数前提下，利用历史交易收益 + 完整决策轨迹，由独立策略智能体迭代改写自然语言形式的工具调用策略，让 LLM 交易智能体随市场经验自适应调整分析流程。

## 2. 核心精读问答

### Q1 研究问题：这篇论文试图解决什么问题？

**背景**
LLM 可以融合价格、新闻、研报等异构信息，搭配外部工具做金融推理与资产配置。现有 LLM 交易智能体的工具调用规则、证据校验、风控逻辑全部写在系统提示词中，部署后固定不变。金融市场是非平稳时序环境，市场状态（上涨、回撤、震荡）持续切换，静态提示策略无法自适应调整分析流程。

**现存痛点**

1. 静态提示策略在市场体制切换后失效：工具调用优先级、校验规则、风控逻辑无法随交易经验更新；
2. 单纯增加工具、扩充上下文不能自动提升交易性能，智能体不知道何时 / 如何调用工具；
3. 金融反馈存在严重模糊性：单次收益高低无法区分是策略缺陷还是市场随机噪声，仅用收益信号难以诊断问题；
4. 传统方案二选一：要么离线一次性优化提示词，要么直接学习资产权重（金融强化学习，模型不可解释）。

**研究动机**
不要优化单次资产配置决策，而是优化**控制整个决策流程的可复用工具调用策略**；不微调骨干 LLM，仅迭代自然语言提示文本，实现轻量化、可解释的在线自适应。

**任务目标**
构建一套闭环自演化框架：在冻结交易 LLM、不修改工具接口的前提下，利用多轮交易的真实投资组合收益 + 完整决策轨迹，跨周期更新自然语言策略，持续提升风险调整收益（夏普比率、累计收益）。

### Q2 相关研究：有哪些相关研究？

#### 类别 1：LLM 金融交易智能体

代表工作：FinMem、TradingAgents、StockAgent、QuantAgent、TradExpert、FinAgent，以及 AI-Trader、LiveTradeBench 等评测基准。

- 优势：引入记忆、多智能体、工具调用、多模态信息，LLM 可以融合文本新闻与数值市场数据；
- 缺陷：提示词、工具调用策略部署前固定，**无法利用交易反馈在线迭代**；存在时间泄露、虚假记忆等可靠性问题。

#### 类别 2：LLM 提示优化与自改进智能体

1. 离线提示优化：演化搜索、LLM 自反思优化提示，在固定数据集一次性优化，部署后不再更新；
2. 单步任务内自反思：在单次任务内部修正推理错误，**不跨周期修改长期复用的工具调用策略**；
3. 金融领域演化工作（AlgoEvolve）：直接演化可执行交易代码。

- 缺陷：在线提示优化极少用于带延迟、噪声反馈的时序金融决策；大多优化代码而非自然语言策略。

#### 类别 3：金融强化学习

直接优化资产权重，学习输出资产分配向量。

- 优势：直接最大化收益目标；
- 缺陷：学到的是隐式参数，不可解释；在市场分布偏移时泛化差。

**研究缺口**
缺少**跨交易周期、基于真实投资组合收益 + 完整推理轨迹，持续迭代自然语言工具调用策略**的自演化交易智能体框架。

### Q3 解决方案：论文如何解决这个问题？

#### 1. 整体思路与框架概述

EvolveTrade 是双智能体闭环架构，分为**交易内环**与**策略演化外环**。

- 交易智能体（Trading Agent）：冻结骨干 LLM，接收市场数据、新闻、当前文本策略\(\pi_t\)，调用工具，输出资产权重，保存全部决策轨迹；
- 策略智能体（Policy Agent）：独立 LLM，**低频周期触发**，读取旧策略、周期内全部决策轨迹、投资组合收益反馈，诊断策略缺陷，输出更新后的自然语言策略\(\pi_{t+1}\)；
- 核心思想：**学习对象不是模型权重、不是资产权重，而是自然语言文本形式的策略**，策略定义工具调用、信号校验、风控规则。

#### 2. 模块逐条解释

##### （1）交易智能体 Trading Agent

- **是什么**：冻结参数的 LLM + 一组外部工具；由系统提示策略\(\pi_t\)完全控制行为。
- **为什么用**：保持骨干模型不变，所有行为变化完全来自策略文本修改，保证可解释性，避免模型微调带来的灾难性遗忘。
- **本文怎么用**：输入市场观测、新闻、当前策略；按策略规则调用工具集（行情查询、Python 代码执行、新闻检索、资产分配）；输出资产权重\(w_t\)；保存完整推理与工具调用轨迹。

##### （2）经验反馈模块（收益\(g_t\) + 决策轨迹 Trace）

- **是什么**：\(g_t\)是投资组合收益、净值、波动率等量化结果；Trace 保存每一步工具调用、代码输出、LLM 推理、信号校验全过程。
- **为什么用**：单独收益信号歧义极强，无法区分亏损来自市场随机冲击还是策略流程缺陷；决策轨迹为策略诊断提供推理层面证据。
- **本文怎么用**：每一轮交易周期结束后打包，作为策略智能体的输入。

##### （3）策略智能体 Policy Agent

- **是什么**：独立 LLM，专门负责策略诊断与文本改写，**不执行交易决策**。
- **为什么用**：分离 “交易执行” 和 “策略反思” 两个职责；避免交易时的反思干扰实时决策；专门做跨周期的流程级策略修订。
- **本文怎么用**：输入旧策略、收益、决策轨迹、市场体制标签；诊断问题，仅修改策略流程规则，不改动底层工具与输出格式；输出新版自然语言策略\(\pi_{t+1}\)。

##### （4）闭环迭代机制

- **是什么**：高频交易内环（每日执行资产配置） + 低频策略更新外环（周期触发策略改写）。
- **为什么用**：策略不能每日频繁更新，防止策略震荡、不稳定；低频更新保证策略稳定。
- **本文怎么用**：初始化人工编写初始策略\(\pi_0\)；滚动回测仿真；周期结束触发策略智能体更新策略；新策略投入下一轮交易循环。

### Q4 可复现细节：训练数据、模型结构、实验配置

> 
> 注意：论文无开源代码，部分参数为论文描述，缺少底层实现源码，复现存在一定门槛。

#### 数据集

- 来源：美股高流动性大盘个股（NVDA、AAPL、MSFT 等）
- 时间区间：2024–2025，切分为 6 个相互独立、截断后的市场子区间（6 种市场体制）
  1. Reg1：温和上行
  2. Reg2：快速上涨趋势
  3. Reg3：2025.01 NVDA 回撤案例
  4. Reg4：震荡区间
  5. Reg5：4 月深度回撤
  6. Reg6：9 月上行趋势
- 数据类型：日度收盘价、成交量、技术指标、标的每日财经新闻文本
- 预处理：
  1. 严格规避时间泄露：仅使用交易日当日可获取信息，禁止未来数据；
  2. 新闻清洗，去除广告冗余，保留新闻摘要、分析师观点；
  3. 价格转换为对数收益率用于收益评估。
- 数据集划分：6 个市场体制完全独立，滚动仿真回测，无跨区间训练。

#### 模型结构

- 交易智能体：2 套不同开源 LLM 骨干（LLM-A、LLM-B），**全程冻结，无参数更新**；搭配固定工具集（行情查询、代码执行、新闻检索、资产分配）。
- 策略智能体：独立 LLM，用于读取长文本轨迹，诊断并改写策略提示词。
- 参数量：论文未披露两个 LLM 的具体参数量。
- 特殊设计：双智能体解耦；策略为自然语言文本参数，而非模型权重。

#### 训练设置

> 
> 本文**没有传统神经网络训练、损失函数、优化器**，不属于梯度训练。

- 迭代方式：周期式文本改写，非梯度优化；
- 策略更新轮次：按市场体制周期触发更新，不是逐交易日更新；
- 硬件环境：论文未给出 GPU、显存等硬件信息。

#### 评价指标

1. 累计收益率 CR：期末净值 / 期初净值 −1；衡量总收益；
2. 夏普比率 SR：超额收益率 / 波动率；**风险调整收益，核心指标**；
3. 行为统计指标：代码工具调用频次、各类技术指标（VaR、SMA/EMA/RSI）调用次数。

#### 复现坑点与注意事项

1. 时间泄露是金融回测最大坑：所有数据必须严格使用当日可获取信息；
2. 长文本轨迹输入：策略智能体需要读取大量推理日志，会遇到 LLM 上下文窗口限制；
3. LLM 生成随机性：策略改写存在不确定性，同一套输入，多次运行可能生成不同策略，带来结果方差；
4. 仿真环境必须和论文对齐：资产池、交易成本、仓位约束、最大单资产敞口限制；
5. 缺少开源代码，策略智能体的诊断提示词是核心黑箱，需要自行复写诊断指令。

### Q5 实验部分：论文做了哪些实验？

#### 实验 1：主对比实验（多市场体制 × 两套 LLM 骨干）

**目的**：验证 EvolveTrade 相比静态策略基线，能否提升夏普比率、累计收益。
**设置**
基线：

1. EvolveTrade（LLM-A）
2. Static Tool-Calling Agent（LLM-A，固定初始策略）
3. EvolveTrade（LLM-B）
4. Static Tool-Calling Agent（LLM-B，固定初始策略）
5. Buy & Hold（等权买入持有，金融基准）

**核心结果（夏普比率 SR）**

表格

| 模型 / 市场体制 | Reg1 温和上行 | Reg2 快速上涨 | Reg3 2025.01 NVDA 回撤 | Reg4 震荡 | Reg5 4 月深度回撤 | Reg6 9 月上行 |
| --- | --- | --- | --- | --- | --- | --- |
| EvolveTrade（LLM-A） | 0.87 | 1.12 | 0.64 | 0.41 | 0.38 | 1.21 |
| Static Tool-Calling(LLM-A) | 0.74 | 0.95 | 0.42 | 0.33 | 0.19 | 0.97 |

结论：EvolveTrade 在多数市场体制下优于同骨干静态基线；在 3 组模型 - 体制配对同时取得最优 SR+CR；2 组场景静态基线更强。

#### 实验 2：行为分析实验

**目的**：验证性能提升来自策略修改带来的工具调用行为改变，不是随机噪声。
**设置**：统计工具调用记录，对比静态基线与 EvolveTrade 演化后策略的工具使用模式。
**结果**

1. EvolveTrade 显著提升代码定量分析调用频次；静态基线很少调用代码工具；
2. 市场自适应行为：4 月深度回撤自动启用 VaR、信号归一化；9 月上涨趋势优先使用 SMA/EMA/RSI 趋势指标；静态基线不会自动触发；
3. NVDA 回撤案例：演化策略优化仓位规则，带来 + 1.33% 相对日收益。

#### 实验 3：消融实验

**目的**：验证框架核心组件必要性，确认决策轨迹输入的价值。

表格

| 实验组 | 夏普比率 SR | 说明 |
| --- | --- | --- |
| Full EvolveTrade（收益 + 决策轨迹） | 0.64 | 完整框架 |
| 消融 1：仅收益反馈，移除决策轨迹 | 0.43 | 大幅下降，轨迹不可缺少 |
| 消融 2：关闭策略演化，固定初始策略 | 0.42 | 退化为静态基线 |

结论：仅依靠收益无法完成有效策略更新；**决策推理轨迹是策略智能体诊断问题的必要输入**。

### Q6 创新点与可借鉴点

#### 理论创新

1. 将 LLM 交易智能体的工具调用策略抽象为**文本参数化策略**；把策略学习从 “模型权重空间” 转移到自然语言文本空间；
2. 提出在非平稳金融时序场景，**优化流程规则，而不是单次决策或资产权重**的范式。

#### 方法创新

1. 双智能体解耦架构：交易智能体负责执行，独立策略智能体低频跨周期反思改写策略；骨干 LLM 全程冻结；
2. 采用「收益反馈 + 完整决策轨迹」双信号作为策略更新输入，解决金融场景收益模糊、归因困难的痛点。

#### 工程实现创新

1. 轻量化：不需要微调大模型，只修改系统提示词，可直接接入任意冻结 LLM 工具智能体；
2. 策略可解释：演化得到的策略是可读自然语言，不像 RL 学到的隐式权重不可解释。

#### 可借鉴点

1. 对于带延迟模糊反馈的时序智能体任务，可分离执行智能体与反思智能体；
2. 当奖励信号噪声大时，把**推理轨迹作为辅助反馈**，辅助 LLM 诊断失败根源；
3. 把 “策略” 建模为自然语言提示，做在线迭代，避免微调大模型的成本与风险。

### Q7 论文不足与局限性

1. **仅历史仿真回测，无实盘验证**：历史回测存在过拟合风险；极端黑天鹅市场发生分布跳变时，演化策略依然失效。
2. **策略改写存在随机性**：策略智能体是 LLM，文本生成存在随机；部分迭代轮次会出现策略退化，引入错误规则，造成短期收益下滑；缺少策略校验、回滚保护机制。
3. **数据集覆盖有限**：仅美股大盘流动性个股；不支持债券、商品、小盘股；评测时间窗口仅 2024–2025，缺少超长熊市验证。
4. **计算开销高**：策略更新时，策略 LLM 需要读取全部长决策轨迹，长周期运行推理成本高。
5. **范式固有上限**：策略必须能用自然语言描述；如果最优交易逻辑无法用文字规则表达，该框架无法学习。
6. 未研究策略更新频率的超参扫描，更新周期对稳定性的影响缺少系统性消融。

## 3. 范式提炼（提取这篇文章的主要研究范式）

### 逻辑范式

**背景：LLM 工具智能体在非平稳环境中，静态提示策略无法自适应 → 痛点：奖励反馈噪声大，传统 RL 不可解释，离线提示优化不能在线更新 → 方案：双智能体闭环，把策略表示为自然语言文本，利用收益 + 推理轨迹低频迭代策略，骨干模型冻结 → 验证：多市场体制回测、行为分析、消融验证组件必要性 → 结论：文本策略在线演化是提升 LLM 交易智能体鲁棒性的有效方向。**

### 技术范式

**通用套路：对于带噪声、延迟奖励的时序决策任务**

1. 分离执行智能体与反思智能体；执行智能体冻结，不做参数更新；
2. 将智能体的行为策略编码为自然语言文本（提示词），作为可学习对象；
3. 奖励信号模糊时，**配套完整推理 / 执行轨迹作为辅助诊断信息**；
4. 采用低频周期式更新，避免高频更新带来的策略震荡；
5. 评估不只看最终任务指标，增加行为层面分析，验证机制有效性，不只看收益数字。

> 
> 可迁移场景：机器人任务规划、复杂工具调用智能体、多步决策 Agent，凡是奖励信号模糊、环境非平稳、不希望微调大模型的场景。

## 4. 后续研究拓展

### 值得进一步做的研究话题

1. 增加策略安全校验层：对新生成策略做仿真预测试，策略退化时自动回滚到上一版可靠策略；
2. 多智能体协同演化：多个交易智能体并行演化策略，策略池做优胜劣汰；
3. 跨资产泛化：扩展到债券、商品、外汇、小盘股，测试跨资产迁移能力；
4. 策略压缩与摘要：解决长决策轨迹带来的上下文窗口与成本问题；
5. 结合元学习：让策略智能体识别市场体制，自动选择对应策略更新规则；
6. 实盘模拟、滑点与交易成本更精细的仿真环境，降低回测过拟合。

### 研究主题 / 问题等

- 上位类：**LLM 自主智能体的在线自适应提示演化、带延迟噪声奖励的 Agent 自改进**
- 下位类：**金融交易场景 LLM 工具智能体、非平稳时序环境下的文本策略优化**
- 同位类：LLM Agent 的自反思、提示词演化、工具调用策略优化（其他领域如机器人、代码智能体）

### 数据类型等

- 当前：日度价格、成交量、财经新闻文本；
- 拓展方向：高频分钟数据、财报文本、社交媒体情绪、宏观指标；多资产类别数据。

### 研究设计等

1. 超参扫描：系统研究策略更新周期、轨迹采样长度对性能与稳定性的影响；
2. 鲁棒性测试：分布外极端市场、黑天鹅事件压力测试；
3. 不确定性量化：评估 LLM 改写策略带来的结果方差；
4. 人类评估：人工标注策略修改是否合理，区分有效策略改进与无效文本改写。
