# FactorEngine 论文概要（结构化阅读）

> arXiv:2603.16365v3 ｜ 林钦泓、冯瑞涛、冯英伦、黄振鑫、陈宇坤、杨中梁、周琳娜、费斌杰、刘嘉琦、李玉 ｜ 北京邮电大学 + 北京量匀科技等

## 一句话

把因子当"满足输入输出契约的可执行程序"，用三层分离（改逻辑 vs 按市况定参数、LLM 定向搜索 vs 贝叶斯局部搜索、LLM 推理 vs 本地算力）把因子挖掘做成程序级进化，并用多智能体把研报直接翻成可执行因子做种子。

## 一、三类方法的三个缺口

- 符号表达式法：算子空间是人定的，表达力边界被永久写死，新算子要专家设计语义与组合规则。
- 神经网络法：预测强但不可解释、易过拟合、遇状态切换易崩。
- 现有 LLM 法：把语义搜索和数值调参混在一个昂贵循环里——比如 corr5 与 corr60 逻辑相同、只是窗口不同（编码的是不同的市场状态），这种"按市况实例化参数"的工作不需要 LLM 反复推理，却把 API 预算烧在这里，还让参数噪声污染逻辑信号；同时外部的研报知识多半只被当作上下文刺激，没被转成可执行因子。

## 二、方法：三层分离 + 知识注入 + 经验反馈

- **程序级因子**：因子 = 满足显式输入输出契约的可执行代码（不是固定算子文法里的表达式）。
- **宏层**：LLM 提出"参数化的逻辑族"（计算结构 + 可变参数范围），负责语义探索。
- **微层**：贝叶斯优化在给定逻辑族上做按市况的参数实例化，快速本地验证并把反馈回灌。
- **知识注入的启动模块**：抽取—验证—代码生成的多 agent 闭环，把非结构化研报转成可执行种子因子，形成"知识注入池"。
- **轨迹感知的改进**：未来的变异条件化在过去的执行历史（累积的进化经验链）上。
- **集成选择**：从进化池里挑精英因子训练模型、回测，得到组合层反馈。

## 三、关键结果（CSI300 与 CSI500，真实 OHLCV）

- 两种配置：**FE-alpha**（用手工标准因子初始化）与 **FE-report**（研报知识初始化）。
- FE-alpha 在 IC/ICIR、Rank IC/RankICIR、年化收益与 Sharpe 上全面超过基线，且在同等信息预算下因子多样性更好。
- **FE-report 相对 Alpha158**：信息系数（IC）提升 **58%**，超额年化收益提升 **126%**——这是"研报→可执行程序"这条路径最直接的数字证据。

## 四、与库内其他论文的关系

- 与 **12 R&D-Agent(Q)** 是同一栏的正面对手：都以"因子即可执行代码"为前提，但 12 靠多单元 + 老虎机调度全流程自动化，14 靠宏微分离把 LLM 与局部搜索各归各位。
- 与 **07 QuantEvolver** 呼应：都把"评估反馈"当作进化的燃料，07 把反馈搬进模型权重，14 把反馈搬进经验链与贝叶斯先验。
- 与 **16 X-Alpha** 的关键差别在于"记忆放在哪"：X-Alpha 建持久研究记忆（跨周期改研究方向），FactorEngine 用轨迹意识做本轮内的变异条件化。
- 与 **01 AQuA** 共享"可审计"这条底线：程序级因子天然可读、可复盘。

## 五、局限

- 结论主要建立在 CSI300/CSI500 两个中国市场股票池上，跨市场迁移未大规模验证。
- 贝叶斯微层仍需对每个逻辑族跑大量回测，算力成本与逻辑族规模强相关。
- 研报启动模块的收益依赖研报质量与"是否能落到日频量价契约"，超出日频数据可得范围的想法会被自动过滤掉。
