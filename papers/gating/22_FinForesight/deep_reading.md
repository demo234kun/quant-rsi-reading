## 2. 核心精读问答

### Q1 研究问题：这篇论文试图解决什么问题？

**评估"金融深度研究系统"的时序有效性难题。** 三种评估方式各有致命缺陷：

- **历史回测**：可能奖励"模型记住了结果"或"检索到了预测日之后才发布的信息"，分数虚高。
- **实时预测（live）**：干净，但必须等事件落地才有反馈，模型与系统迭代拿不到"当天就能用的分数"。
- **跨市场/跨任务的聚合分**：把"选股排序""事件方向""财务预测"混成一个数，掩盖具体能力差异。

所以论文要回答三个问题：（1）能不能构造一种"已落地但未被记忆污染"的回测，既及时又干净？（2）不同时间制度的分数差到底来自能力还是来自记忆？（3）检索控制做到什么程度，历史回测才真正等价于实时预测？

### Q2 相关研究：有哪些相关研究？

- **时序有效性线**：live forecasting（Karger 等 2024；Zeng 等 2025）、pastcasting（用重建的历史证据评已解决的问题）、冻结检索环境的可复现 agent 评估（FutureSearch 2025；Ye 等 2026）、把历史预测市场回放做回顾式预测（Wildman 2025；Chai 2026）。但"受控历史回测能否可靠反映实时表现"在金融任务上仍不清楚。
- **泄漏风险线**：模型可能回忆历史财务结果，且"不要使用未来知识"的指令常常无效（Didisheim 2025；Li 2026c）；按日期过滤的检索仍可能暴露预测日不可得的信息，因此需要显式的前视审计（Lahib 2026；Benhenda 2026）。
- **金融 agent 基准线**：FinTradeBench（基本面 vs 技术面信号推理）、DeepFund（市场环境中的投资决策）、代码式 alpha 挖掘基准。论文批评它们的"聚合分"会掩盖具体未来结果预测能力。

### Q3 方法：具体怎么做？

**三层设计：任务族 → 时间制度 → 时序受控评测框架。**

**(1) 六个任务族（三市场 CN / US / HK，共 1,119 条记录）**

| 任务 | 内容 | 记录数 | 评分 |
|---|---|---|---|
| VAL 估值 | 给 bear/base/bull 三档目标价 + 回归时间桶 | 244 | 相对"预测日收盘价"基线的误差缩减 + 回归期命中率，各占一半 |
| RANK 收益排序 | 行业内同业按未来超额收益排序（纯基本面 / 纯技术 / 混合三变体） | 383 | 归一化 Spearman + Top-K 命中（K=⌊N/3⌋） |
| EVT 事件方向 | 财报 / 政策 / 宏观事件后的收益方向与上行概率 | 138 | Brier skill |
| FUND 财务预测 | 预测尚未披露的财务指标 | 294 | 截断的单条效用 |
| CF 反事实 | 成对虚构公告（含与历史趋势冲突的情形）判断方向 | 30 | 是否遵循注入的事件逻辑（能力诊断，单独计分） |
| CALC 计算 | 多步财务数值推理，含干扰值与单位/惯例陷阱 | 30 | 中间与最终步骤的容差 Exact Match |

（来源：正文 §3.2 + 附录 A；四类结果导向任务构成 Overall 分，CF 与 CALC **不计入** Overall。）

**(2) 三个时间制度（按每个模型的知识截止日 c_m 动态划分）**

- **T1 预训练期**：预测日与结果日都早于 c_m → 结果可能被记住，天然虚高。
- **T2 截止后已落地**：预测日晚于 c_m，结果在预测日与评估日之间已落地 → **当天就能打分**，是主评测集。
- **T3 真·实时**：预测时结果未知，只能等落地后评分。
- 数据构造口径：T1 用 2024-06-01 前的预测日，T2 用 2025-07-31 之后，并对齐共同的可比实例。

**(3) 时序受控回测框架**

- 模型 × harness × 检索策略由控制器统一配置；**参考标签只对评估器可见**，系统侧只经中介服务访问搜索与行情工具，全部交互留痕用于证据审计。
- 响应在打分前**锁定**。
- **三种检索策略**：裸搜索（无时间检查）→ PIT（时点控制，按时点戳与历史版本拒绝预测日之后发布的页面）→ PIT + LLM 泄漏过滤（用 DeepSeek-V4-Flash 2026-04 版判定"是否含未来信息、时序模糊、分类不确定"，命中即拒）。
- **诊断量**：Δ(T1,T2) 看历史优势；Δ(T2,T3) 看回测与实时的贴合度；Prompt Change Rate / Perturb Change Rate 看改写的敏感度。

**(4) 被测系统**：5 个 harness（FinanceHarness、Open Deep Research、GPT-Researcher、Claude Code、Codex）× 8 个模型（GPT-4.1-mini、Claude Sonnet 4.5、Claude Opus 4.6、Gemini 3.1 Flash-Lite、Gemma 3、Phi-4、DeepSeek-V4-Flash、GPT-5.4）= **22 个组合**。选型刻意偏向"时间可比"而非"最新"。

### Q4 实验设置：数据、基线、指标？

- **数据来源**：价格 Yahoo Finance；财报与财务值 SEC EDGAR、巨潮、上交所、深交所、HKEXnews；宏观事件取自美国 BLS、中国国家统计局、香港统计处。数据构造与结果标签采集**独立进行**，以确认信息在预测日可得。
- **基线**：无外部"金标准"基线，横向比较的是 22 个 model–harness 组合本身；另有"预测日收盘价"作为 VAL 的显式误差基线。
- **指标**：四任务各自的 outcome 分数 + Overall（四者等权）；CF / CALC 单独报告；诊断量为 Δ(T1,T2)、Δ(T2,T3)、PCR、NCR、Score Delta。

### Q5 主要结果：数字是什么？

**（a）T2 主榜（Table 1，22 个组合）**

- Overall 区间约 0.56–0.71。最高是 **Gemini 3.1 Flash-Lite + GPT-Researcher = 0.7099**，其次 FinanceHarness 下的 Gemini 3.1 Flash-Lite 0.7049、DeepSeek-V4-Flash 0.7031。
- **任务间分化极大**：VAL 普遍 0.62–0.90（Phi-4 最高 0.8956），而 RANK 普遍只有 0.44–0.50——几乎是随机排序水平。
- **金融专用 harness 不持续占优**：FinanceHarness 在六个共享模型上平均最高，但 DeepSeek-V4-Flash 与 Gemini 3.1 Flash-Lite 都在 GPT-Researcher 下表现最好。**能力分（CF/CALC）高 ≠ 预测分高**：Claude Code 下 Claude Sonnet 4.5 Overall 仅 0.6292，但 CF/CALC 都是 1.0000。

**（b）T1 与 T2 的差（Table 2 / Table 5）**

- 27 个"模型–任务–市场"比较里 **25 个 T1 更高**；所有 RANK 与 FUND 的差都为正；唯二例外是 HK 的 EVT。
- **CN 的 FUND 差最夸张：0.3503–0.4469**（Claude Sonnet 4.5 CN FUND：T1 0.9997 vs T2 0.5655）。
- 说明历史成绩的"优势"很大一部分来自记忆，而不是能力。

**（c）T2 与 T3 的贴合度（Table 3 / Table 6，US 匹配一周窗口，9 个模型–任务对）**

| 检索策略 | 平均绝对 Δ(T2,T3) |
|---|---|
| 裸搜索 | 0.1203 |
| + PIT | 0.0618 |
| + PIT + LLM 过滤 | **0.0285**（比裸搜索降约 76%） |

- 加过滤后**九个比较全部收窄**，EVT 与 FUND 都达到最贴；RANK 在 Claude Sonnet 4.5 与 Gemini 3.1 Flash-Lite 上 PIT 单用最好。
- 实时 T3 真实成绩：EVT 0.5805–0.5926、FUND 0.7194–0.8563；最极端的收窄是 Claude Sonnet 4.5 EVT：裸搜索 0.8232 → 过滤后 0.6006，T3 0.5926。

**（d）输入稳健性**

- Prompt Change Rate **16.83%–23.67%** > Perturb Change Rate **7.00%–9.17%**——**改说法比改数字更容易改变具体预测**。
- 但 Score Delta 在四种配置下**绝对值都 < 0.0026**：单条预测会变，聚合分几乎不动。

**（e）市场层**

- 六个模型都是**美国市场平均分最高**；CN 领先者是 DeepSeek-V4-Flash（0.6825），US 与 HK 领先者都是 Gemini 3.1 Flash-Lite（0.7480 / 0.6698）。

### Q6 消融与鲁棒性：哪些因素影响结论？

- **检索策略是最大变量**：同一模型同一任务，从裸搜索到过滤，分数可掉 0.02（GPT-4.1-mini EVT 0.0599→... 过滤后 T2 0.5847）乃至 0.22（Claude Sonnet 4.5 EVT 0.8232→0.6006）。论文的结论因此是"信息可得性主导回溯分数，远超输入措辞的影响"。
- **时间制度**：T1 全面偏高，且 CN 的 FUND 最严重——任务越"可被记住"（财务指标、历史排序），历史优势越明显。
- **模型 vs harness 的交互**：harness 优势依赖底座模型，没有单一 harness 全面压制。
- **输入扰动**：措辞与数值扰动改变个体预测但不改变聚合结论（Score Delta < 0.0026），可视为"任务理解稳定"的证据。
- **市场**：同一模型跨市场表现会翻转（如 GPT-4.1-mini 在 HK 以 FinanceHarness 与 Open Deep Research 最高、在 US 以 GPT-Researcher 最高），说明"哪个 harness 好"本身是市场依赖的。

### Q7 局限与威胁：这份基准自己漏了什么？

- **评测规模与 T3 覆盖很薄**：T3 参考分只有 **US 的 12 个模型–任务组合**、且是**一周匹配窗口**；CN/HK 没有 T3，表 5 里是"—"（论文明确说明是"未报告"而非"预测失败"）。
- **只在三个模型上做 T2–T3 对齐**（GPT-4.1-mini、Gemini 3.1 Flash-Lite、Claude Sonnet 4.5），且 VAL 被排除在聚焦分析外（对短期价格波动过敏感）。
- **模型选型牺牲了新鲜度**：为了共享同一 T2 窗口，八个模型都在 T2 窗口前后，前沿模型（GPT-5.4 / Claude Opus 4.6）只在 Codex / Claude Code 两个 harness 上出现。
- **"已落地"的时效性有限**：T2 用 2025-07-31 之后的预测日，基准自身的 T2 池会随真实时间推进而老化，需要不断重建。
- **泄漏过滤依赖另一个 LLM**：用 DeepSeek-V4-Flash 判"是否含未来信息"，等于把一部分评估效度外包给一个可能出错的模型，且仍有"页面时点戳早于实际更新"这类 PIT 无法解决的残留。
- **任务本身的天花板**：RANK 分数普遍 0.44–0.50，说明该类任务对现有系统近乎不可解——这既可能是系统的局限，也可能是评分口径（Spearman + Top-K 平均）过严，论文未做口径敏感性分析。

## 3. 范式提炼

一句话：**把"评估"做成受控实验，而不是排行榜。**

三条可迁移的做法：

1. **按模型知识截止日切时间制度**，而不是按日历切——同一批题，对不同模型属于 T1/T2/T3 不同性质，分数才可比。
2. **把"检索策略"作为显式自变量**（裸搜索 → PIT → LLM 过滤），于是"分数"从单一数值变成"在某个信息可得性条件下取得的分数"，泄漏诊断从定性怀疑变成定量收窄。
3. **预测分与能力分分离计分**：CF / CALC 单独报，避免"会算数"冒充"会预测"。

对本库的意义：它是"**门槛控制**"这一栏最锋利的一篇——不是靠规则卡住模型，而是靠**证据时点**卡住分数。任何"我的 agent 回测 Sharpe 很高"的说法，都该先过这道时序审计。

## 4. 后续拓展

- **与 LiveOption（23）互补**：23 在期权里发现现成 agent 普遍跑不赢基准，22 解释了"为什么很多看起来能跑赢的回测其实是被记忆与后发信息抬高的"——两者合起来是对"LLM 交易 agent 正收益"的双重审查。
- **与 SOTA（25）对照**：25 用 2024-09 至 2025-08 的严格时间切分训练，正合 22 的时序纪律；但 25 的测试期（2025-03 至 2025-08）是否落在各模型知识截止之后，需要单独核。
- **论文自己的下一步就是本库的主题**：用新鲜 T2 反馈驱动 autoresearch 系统去提升 T3 预测，从而在金融里探测递归自我改进（RSI）。
- **可执行清单**：把自己的回测改成"三重审计"——① 预测日 vs 模型截止日；② 证据时点戳 vs 预测日；③ 同一模型在 T2 与 T3 的分数差。三条都过，分数才算数。
