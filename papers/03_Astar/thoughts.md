# Astar 个人思考

## 最该抄走的不是 8B 模型，是数据工程管线

Astar 真正的工程量在"把几百条 commit 变成几万条可训练样本"：可达性分析、AST 归一、配置白名单、语义过滤。这套动作和清洗另类数据是同一门手艺——**先定义什么算信号，再谈模型**。个人做研究时，自己的实验日志如果不结构化沉淀，就永远没有"自己的经验库"。

## 奖励模型是最危险也最迷人的零件

AUC 0.8487 意味着教练比人和通用模型都准，但 15% 的错同时流进三个地方。论文的防线（增量校准 + 真实 A/B）是工程解，不是理论解。这和 01_AQuA 形成鲜明对照：
- AQuA：裁判焊死，宁可只能评 DSL 内任务；
- Astar：裁判放进环内，赌外圈真实 A/B 能兜底。

做个人系统时，如果任务有便宜的真实裁判（比如一个小样本回测），学 Astar；如果没有便宜裁判，学 AQuA 把范围砍小。

## "经验没有贬值，它变成了训练数据"

这句话是给工程师的。个人开发者真正的护城河不是模型，是**自己系统里那几百次 commit 的成败记录**——别人拿不到。

## 与本库其他文章的关系

- 它是 05_RSI_ThreeReins 里**缰绳一（裁判）用环内学习型替代裁判**的样本。
- 它的 GMV +4.86% 是本库唯一有真实业务 A/B 的数字——比任何 Sharpe 都结实。
- 它和 04_Dream-RSI 是两种 τ：Astar 把改进传回改进者本身（重训练），Dream-RSI 把改进留在元策略层（不重训）。
