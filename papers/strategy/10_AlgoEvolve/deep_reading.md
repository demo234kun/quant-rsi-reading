# AlgoEvolve 论文概要（结构化阅读）

> arXiv:2606.26173v1 ｜ Dhruv Sharma, Gautam Shroff ｜ 德里英迪拉·甘地信息技术学院（IIIT Delhi）

## 一句话

把 LLM 当成"语义变异算子"，在可执行 Python 交易策略的种群上做进化；外面再套一层**元进化**——连"怎么搜"的提示词本身也被进化，最终年化 Sharpe 5.60。

## 一、要解决的问题

算法交易里策略表现是参数的**非可微、高度不连续**函数（噪声大、信噪比极低），深度学习和强化学习靠黑箱参数优化，既不可解释又容易过拟合历史噪声，遇到状态切换（regime shift）就崩。已有的 LLM 交易系统多半是"运行时调用模型做决策"，带来推理延迟、不可解释、成本高。

作者的主张是把 LLM 从"实时交易员"改成**"策略设计者"**：只在设计阶段用 LLM，跑实盘阶段是纯程序，零推理延迟、天然可解释。

## 二、方法：内外两层循环

- **内层（策略进化）**：策略 = 可执行 Python 程序。每一代：提示构建 agent 组装上下文（搜索提示 + 当前策略代码 + 最近表现）→ LLM 做语义变异 / 交叉 → 新策略进种群 → 回测器按严格 walk-forward（滚动前向）协议打分 → 排序与选择，留下精英进入下一代。
- **外层（元进化）**：把"搜索提示"本身当作**提示基因组**，由元进化 agent 做交叉与语义变异，目标是发现更好的搜索启发式——例如更好地平衡探索与利用、减少"零交易"失败（生成的策略一行不下单，回测直接空转）。
- 关键差异：以往方法靠静态指令或非结构化反馈，AlgoEvolve 让系统自己学会"该怎么搜"。

## 三、关键结果

- **端到端效果**：年化 Sharpe 达到 **5.60**。
- **涌现的状态自适应逻辑**：系统会自主放弃人类给的趋势跟随先验，转向多因子打分、价格行为启发式等更复杂的规则；这些策略常用多根 K 线组合的模式，形态上像人类工程化的结构，但参数是针对目标资产的波动特性优化出来的。
- **元进化的收益**：外层进化出的提示持续优于初始人工指令，显著压低"零交易"失败率。
- **工程价值**：部署阶段完全不调模型，零推理延迟。

## 四、与库内其他论文的关系

- 与 **09 SHARP** 是"表述方式"的两条路：09 用人类可读规则束（可审计、表达力弱），10 用可执行代码（表达力强、审计要靠读代码）。
- 与 **05 FunSearch / AlphaEvolve 一脉**（作者明确对标）属于同一思想谱系：LLM 作变异算子 + 回测作适应度。
- 与 **08 EvolveTrade** 互补：08 进化的是自然语言 policy（运行时还要调模型），10 进化的是程序（运行时不需要模型）。
- 对本库"策略进化"栏的意义：它给出一个"元层也被进化"的完整范式——不只是策略在进化，搜策略的方法也在进化。

## 五、局限

- 适应度仍来自历史回测的盈亏，论文强调 walk-forward，但过拟合风险不可能完全消除（Sharpe 5.60 这个量级在真实资金上需要极强的样本外验证）。
- 只在单一/少数资产上报告，跨市场、跨资产类别的迁移性未充分展开。
- 元进化需要额外算力，成本结构论文交代较简。
